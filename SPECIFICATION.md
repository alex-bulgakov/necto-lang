# Официальная спецификация языка программирования Necto 2.0 (Стандарт)

> **Статус документа:** Официальный стандарт языка и эталонное руководство  
> **Версия языка:** `2.0.0 (Pure Self-Hosting & Embedded Toolchain)`  
> **Последнее обновление:** 2026-09-03  

---

## 1. Введение и философия дизайна

**Necto** (от латинского *nectere / necto* — *«связывать воедино», «сплетать»*) — универсальный системный язык программирования со статической типизацией, объединяющий безопасность, выразительность и высокую производительность без пауз сборщика мусора (GC).

### Ключевые архитектурные принципы:
1. **Безопасность по умолчанию:** Переменные неизменяемы по умолчанию (`let`), отсутствие `null`/`nil` (вместо них `Option[T]`), отсутствие неконтролируемых исключений (вместо них `Result[T, E]` и оператор `?`).
2. **Алгебраическая выразительность:** Tagged Enums с полезной нагрузкой и сопоставление с образцом (`match`) позволяют моделировать предметную область без скрытых состояний.
3. **Нулевая стоимость абстракций:** Программы могут компилироваться напрямую в машинный код через LLVM/Clang или исполняться мгновенно через встроенный интерпретатор.
4. **Прозрачное управление памятью:** Умные указатели `Box[T]` обеспечивают явное размещение рекурсивных структур данных (деревьев AST, списков, графов) в куче.
5. **Встроенный тулчейн разработчика:** Поддержка тестирования (`test "name" { ... }`), сборки, проверки типов и REPL встроена в единый бинарный файл `necto`.

## 2. Лексическая структура

### 2.1. Исходные файлы и кодировка
* Исходные файлы компилируются из кодировки **UTF-8**.
* Расширение файлов по умолчанию: **`.nc`** (допустимы алиасы `.necto`, `.aura`).

### 2.2. Комментарии
* **Однострочные комментарии:** начинаются с `//` и длятся до конца текущей строки.
  ```necto
  // Это однострочный комментарий
  ```
* **Многострочные комментарии:** обрамляются `/* ... */`.
  ```necto
  /* Это многострочный
     комментарий */
  ```

### 2.3. Идентификаторы и ключевые слова
Идентификаторы начинаются с буквы (`a-z`, `A-Z`) или знака подчеркивания `_`, за которыми могут следовать буквы, цифры или `_`.

Зарезервированные ключевые слова:
```
let       mut       fn        return    if        else
while     for       in        break     continue  struct
impl      enum      match     type      comptime  import
from      package   pub       test      assert    true
false     Some      None
```

### 2.4. Литералы
* **Целые числа (int):** 64-битные знаковые целые числа (`42`, `0`, `-100`).
* **Числа с плавающей точкой (float):** 64-битные числа стандарта IEEE-754 (`3.1415`, `0.0`, `-2.5`).
* **Логические (bool):** `true`, `false`.
* **Строки (str):** строковые литералы в двойных кавычках (`"Hello, Necto!"`).
* **Интерполированные F-строки (f-str):** строки с префиксом `f"..."`, внутри которых в фигурных скобках `{expr}` вычисляются произвольные выражения:
  ```necto
  let x = 10
  println(f"Value is {x * 2}!") // "Value is 20!"
  ```

## 3. Система типов

Necto обладает сильной статической системой типов со строгой проверкой во время компиляции.

### 3.1. Примитивные типы
| Тип | Описание | Пример значения |
| :--- | :--- | :--- |
| `int` | 64-битное знаковое целое число | `42`, `-7` |
| `float` | 64-битное число с плавающей точкой | `3.14` |
| `bool` | Логический тип | `true`, `false` |
| `str` | Неизменяемая строка в UTF-8 | `"text"` |
| `void` | Отсутствие возвращаемого значения | — |
| `any` | Универсальный тип для полиморфизма | Любое значение |

### 3.2. Пользовательские структуры (`struct`)
Структуры представляют собой именованные составные типы:
```necto
struct Point {
    x: int
    y: int
}

let p = Point { x: 10, y: 20 }
```

### 3.3. Tagged Enums (Алгебраические типы данных с полезной нагрузкой)
Перечисления могут содержать варианты как без аргументов, так и с полезной нагрузкой:
```necto
enum Token {
    Number(int)
    Ident(str)
    Plus
    Eof
}
```

### 3.4. Умный указатель `Box[T]` (Косвенность в куче)
Для создания рекурсивных структур данных (деревьев, связных списков):
```necto
enum Expr {
    Num(int)
    Binary(op: str, left: Box[Expr], right: Box[Expr])
}

let tree = Expr.Binary("+", Box.new(Expr.Num(2)), Box.new(Expr.Num(3)))
```
* **Создание:** `Box.new(value)`.
* **Разыменование:** явный метод `.unwrap()` или прозрачное обращение к полям/методам внутреннего значения.

### 3.5. Безопасность значений и отсутствие `null`: `Option[T]`
```necto
let opt: Option[int] = Some(42)
let empty: Option[int] = None

match opt {
    Some(val) => println(f"Value: {val}"),
    None => println("No value"),
}
```

### 3.6. Безопасная обработка ошибок: `Result[T, E]` и оператор `?`
* `Result.Ok(value)` — успешный результат операции.
* `Result.Err(error)` — ошибка выполнения.
* Оператор `?` (Try operator):
  ```necto
  fn read_config(path: str) -> Result[str, str] {
      let data = fs.read_file(path)? // При ошибке функция немедленно вернет Result.Err
      return Result.Ok(data)
  }
  ```

### 3.7. Коллекции
* **Динамические массивы (`[T]`):** изменяемые непрерывные массивы.
  ```necto
  let mut list: [int] = [1, 2, 3]
  list.push(4)
  let last = list.pop() // Option[int]
  ```
* **Хеш-таблицы (`Map[K, V]`):**
  ```necto
  let m = Map.new()
  m.set("key", 100)
  let v = m.get("key") // Option[V]
  ```

### 3.8. Обобщённые типы (Generics)
Параметры типов задаются в квадратных скобках:
```necto
struct Stack[T] {
    items: [T]
}

fn identity[T](val: T) -> T {
    return val
}
```

## 4. Объявления и операторы

### 4.1. Связывание переменных (`let` и `let mut`)
По умолчанию переменные неизменяемы. Для изменения требуется ключевое слово `mut`:
```necto
let x = 10        // Неизменяемая
let mut y = 20    // Изменяемая
y += 5
```

### 4.2. Функции (`fn`)
```necto
fn add(a: int, b: int) -> int {
    return a + b
}
```

### 4.3. Блоки `impl` и методы структур
Методы группируются в блоках `impl`. Метод принимает `self` (неизменяемая ссылка) или `mut self` (изменяемая ссылка):
```necto
struct Counter {
    val: int
}

impl Counter {
    // Статический метод-конструктор
    fn new(start: int) -> Counter {
        return Counter { val: start }
    }

    // Изменяемый метод экземпляра
    fn inc(mut self, step: int) {
        self.val += step
    }

    // Неизменяемый метод экземпляра
    fn get(self) -> int {
        return self.val
    }
}
```

### 4.4. Сопоставление с образцом (`match`)
Конструкция `match` проверяет совпадение по значению, вариантам перечислений, `Option` и `Result`:
```necto
match status {
    Result.Ok(value) => println(f"Success: {value}"),
    Result.Err(err)   => println(f"Error: {err}"),
}
```

### 4.5. Управляющие конструкции
* **Условный переход (`if / else`):**
  ```necto
  if x > 0 {
      println("Positive")
  } else if x == 0 {
      println("Zero")
  } else {
      println("Negative")
  }
  ```
* **Цикл `while`:**
  ```necto
  while i < 10 {
      i += 1
  }
  ```
* **Цикл `for in`:**
  ```necto
  for i in 0..10 {
      println(f"{i}")
  }

  for item in list {
      println(f"{item}")
  }
  ```
* **Операторы `break` и `continue`:** досрочный выход или переход к следующей итерации цикла.

### 4.6. Модули и `import`
Импорт символов из других файлов `.nc`:
```necto
import { add, multiply } from "./math_utils.nc"
```

### 4.7. Встроенные юнит-тесты (`test` и `assert`)
Тесты объявляются в коде нативного модуля:
```necto
test "arithmetic verification" {
    assert(2 + 2 == 4)
    assert(10 > 5, "Math sanity check")
}
```
Запуск всех тестов в файле осуществляется командой `necto test <file.nc>`.

### 4.8. Взаимодействие с языком Си (C Foreign Function Interface / `extern "C"`)
Necto поддерживает прямое объявление и вызов функций внешних библиотек Си без необходимости написания C-обёрток:
```necto
extern "C" {
    fn puts(s: str) -> int
    fn sqrt(x: float) -> float
    fn abs(x: int) -> int
    fn sin(x: float) -> float
    fn pow(base: float, exp: float) -> float
}

fn main() {
    let root = sqrt(144.0) // 12.0
    println(f"Root: {root}")
}
```
* **Соглашение о вызове:** по умолчанию используется стандартное ABI `"C"`.
* **Линковка:** при нативной компиляции (`necto build`) компилятор связывает вызовы со стандартными системными библиотеками (`libc`, `libm`) или внешними `.lib` / `.a`.
* **Интерпретация:** встроенный интерпретатор (`necto run`) поддерживает прозрачный вызов математических и стандартных функций ввода-вывода.

### 4.9. Встроенные бенчмарки (`bench`)
Necto включает первоклассную поддержку профилирования производительности прямо в коде:
```necto
bench "fibonacci calculation" {
    fib(20)
}
```
Запуск бенчмарков осуществляется командой:
```powershell
necto bench [file.nc] [--runs N]
```
Инструмент автоматически калибрует число итераций, замеряет длительность одного вызова в наносекундах (`ns/op` или `µs/op`) и вычисляет пропускную способность (`ops/s`).

### 4.10. Документирование кода (`///`) и `necto doc`
Комментарии, начинающиеся с трёх слэшей (`///`), являются официальными doc-комментариями Necto и привязываются к следующим за ними объявлениям функций, структур, вариантов перечислений и методов:
```necto
/// Вычисляет корень числа
fn calc_root(x: float) -> float { ... }
```
Команда генерации документации создает автономный интерактивный веб-сайт с поиском и структурой типов:
```powershell
necto doc [target] [--output docs] [--serve]
```

### 4.11. Конкурентность и параллелизм (`spawn`, `Channel[T]`, `sleep`)
Necto предоставляет легковесную модель конкурентности, основанную на запуске фоновых задач и безопасной передаче сообщений через типизированные каналы.

#### `spawn(fn, ...args)` — запуск фоновой задачи
```necto
fn worker(ch: Channel, id: int) {
    ch.send(id * id)
}
spawn(worker, ch, 5)
```
Функция `spawn` запускает переданную функцию `fn` в параллельном потоке (горутине), передавая ей дополнительные аргументы.

#### `Channel.new(capacity: int)` — создание типизированного канала
```necto
let ch = Channel.new(10) // буферизованный канал на 10 элементов
```

#### Методы канала:
* `ch.send(value)` — отправка значения в канал (блокирует, если буфер заполнен).
* `ch.recv() -> Option[T]` — получение значения из канала. Возвращает `Some(val)` или `None` (если канал закрыт и пуст).
* `ch.close()` — закрытие канала. После закрытия `recv()` возвращает оставшиеся элементы, затем `None`.

#### `sleep(ms: int)` — приостановка текущего потока
```necto
sleep(100) // пауза на 100 миллисекунд
```

## 5. Стандартная библиотека и модули

### 5.1. Встроенные глобальные функции
* `println(...args)`: вывод аргументов через пробел с переносом строки.
* `print(...args)`: вывод аргументов без переноса строки.
* `len(col)`: получение длины массива, строки или словаря.
* `assert(condition, [msg])`: проверка логического условия, выбрасывает `AssertionError` при `false`.
* `clock()`: возвращает текущее время в секундах с высокой точностью (float).

### 5.2. Модуль `fs` (Файловая система)
* `fs.read_file(path: str) -> str`: чтение текстового файла целиком.
* `fs.write_file(path: str, content: str)`: сохранение текста в файл на диске.

### 5.3. Модуль `os` (Операционная система)
* `os.args() -> [str]`: получение списка аргументов командной строки.

### 5.4. Модули `http` и `net` (Сетевой стек и веб-сервер)
* **Модуль `http`:**
  * `http.get(url: str) -> Result[str, str]`: выполнение HTTP GET-запроса, возвращает тело ответа или ошибку сети.
  * `http.post(url: str, body: str) -> Result[str, str]`: отправка POST-запроса с полезной нагрузкой.
  * `http.listen(port: int, handler: fn(path: str) -> str)`: запуск встроенного HTTP веб-сервера на указанном порту.
* **Модуль `net`:**
  * `net.tcp_connect(addr: str) -> Result[str, str]`: проверка и открытие сетевого TCP-соединения.

Пример встроенного веб-сервера:
```necto
fn handle(path: str) -> str {
    if path == "/api/status" {
        return "{\"status\": \"ok\"}"
    }
    return "Hello from Necto Server!"
}

http.listen(8080, handle)
```

### 5.5. Встроенные методы базовых типов
* **Строки (`str`):**
  * `.len() -> int`: длина строки в байтах/символах.
  * `.sub(start: int, end: int) -> str`: получение среза строки.
  * `.char_at(index: int) -> int`: код символа по индексу (ASCII/UTF-8).
  * `.contains(substring: str) -> bool`: проверка наличия подстроки.
* **Массивы (`[T]`):**
  * `.push(item: T)`: добавление элемента в конец массива.
  * `.pop() -> Option[T]`: извлечение последнего элемента.
  * `.len() -> int`: количество элементов.
  * `.clear()`: очистка массива.
* **Словари (`Map[K, V]`):**
  * `.set(key: K, value: V)`: запись значения.
  * `.get(key: K) -> Option[V]`: безопасное чтение значения.
  * `.has(key: K) -> bool`: проверка наличия ключа.
  * `.len() -> int`: количество пар ключ-значение.

## 6. Модели выполнения и CLI инструментарий

Компилятор Necto объединяет два режима выполнения:
```
                       ┌────────────────────────┐
                       │   Necto Source (.nc)   │
                       └───────────┬────────────┘
                                   │
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
       ┌────────────────────────┐    ┌────────────────────────┐
       │     JIT/Interpreter    │    │      AOT Compiler      │
       │   `necto run app.nc`   │    │ `necto build app.nc`   │
       │   (REPL, Тесты, CI)    │    │ (Clang/LLVM -> .exe)   │
       └────────────────────────┘    └────────────────────────┘
```

### Команды командной строки (CLI)
* `necto init [name]` — инициализация нового проекта Necto с файлом `necto.json`, точкой входа `src/main.nc` и тестами `tests/main_test.nc`.
* `necto fmt [file/dir] [--check]` — форматирование исходного кода Necto в канонический стиль.
* `necto run [file.nc]` — непосредственный запуск программы (или точки входа из `necto.json`).
* `necto build [file.nc] -o <out.exe>` — AOT-компиляция программы в нативный машинный код `.exe` через Clang 17 / LLVM.
* `necto bootstrap` — компиляция самохостингового компилятора Necto в автономный бинарник `bin/necto-native.exe` (Self-Hosting Stage 2).
* `necto test [file.nc]` — запуск встроенных блоков `test` в файле или в каталоге `tests/`.
* `necto bench [file.nc] [--runs N]` — запуск блоков производительности `bench` с замером ns/op и ops/sec.
* `necto doc [target] [--serve]` — автоматическая генерация интерактивного сайта документации API.
* `necto install` — установка и обновление внешних зависимостей из `necto.json` в каталог `.necto/deps/`.
* `necto toolchain [status|install]` — проверка и настройка встроенного C/LLVM бэкенда Clang.
* `necto check [file.nc]` — статический синтаксический и семантический анализ типов без выполнения.
* `necto repl` — интерактивная оболочка REPL.
* `necto version` — версия тулчейна.

### 6.2. Самохостинговый компилятор Necto (Self-Hosting: Stage 1, Stage 2 и Stage 3)
Компилятор Necto полностью реализован на самом языке Necto в пакете `compiler/`:
* `compiler/token.nc` — лексемы и ключевые слова языка.
* `compiler/lexer.nc` — посимвольный лексический анализатор (`struct Lexer`) с поддержкой f-строк.
* `compiler/ast.nc` — рекурсивное AST-дерево (`enum Expr`, `enum Stmt`, `Box[T]`, `ImplBlock`, `MethodCall`).
* `compiler/parser.nc` — синтаксический анализатор рекурсивного спуска (`struct Parser`) с поддержкой структур, методов и операторов присваивания.
* `compiler/codegen.nc` — генератор C/LLVM машинного рантайма (`struct Codegen`).
* `compiler/main.nc` — CLI интерфейс самохостингового компилятора с поддержкой `os.args()`, `fs.read_file()` и прямым вызовом C FFI `system()`.

#### Стадии самохостинга (Self-Hosting Pipeline):
1. **Stage 1 (Pure Necto Implementation):** Вся кодовая база компилятора написана на 100% чистом Necto.
2. **Stage 2 (Native Bootstrap):** Команда `necto bootstrap` компилирует `compiler/*.nc` в автономный нативный бинарник `bin/necto-native.exe`.
3. **Stage 3 (Full Independence):** Бинарник `bin/necto-native.exe` способен автономно принимать и компилировать произвольные программы Necto из командной строки без зависимости от рантайма Go.

Автономная сборка компилятора без Go:
```powershell
.\bootstrap.ps1
# или на Windows CMD:
.\bootstrap.bat
```

### 6.3. Манифест проекта `necto.json`
Файл `necto.json` определяет конфигурацию проекта:
```json
{
  "name": "my_application",
  "version": "0.1.0",
  "entry": "src/main.nc",
  "description": "My first Necto project",
  "authors": ["Developer <dev@example.com>"],
  "dependencies": {}
}
```

### 6.4. Поддержка редакторов кода (VS Code / Cursor)
В репозитории доступно официальное расширение в каталоге `editors/vscode/`:
* Полноценная TextMate подсветка синтаксиса (`syntaxes/necto.tmLanguage.json`).
* Автодополнение парных скобок, кавычек и комментариев (`language-configuration.json`).
* Сниппеты для `fn`, `struct`, `impl`, `enum`, `match`, `test` (`snippets/snippets.json`).

### 6.5. Пакетный менеджер (`necto install`) и внешние зависимости
Necto включает встроенный менеджер зависимостей, работающий на основе Git-репозиториев.

Зависимости декларируются в секции `"dependencies"` файла `necto.json`:
```json
{
  "name": "my_app",
  "version": "1.0.0",
  "dependencies": {
    "necto-http-utils": "https://github.com/example/necto-http-utils.git@main",
    "necto-json": "https://github.com/example/necto-json.git@v1.0"
  }
}
```

Команда установки:
```powershell
necto install
```
* Клонирует указанные ветки/теги в изолированный каталог `.necto/deps/<package_name>/`.
* При повторном запуске производит быстрое обновление (`git pull --ff-only`).
* Информирует о количестве загруженных исходных файлов Necto.

### 6.6. Встроенный бэкенд компилятора Clang/LLVM и управление тулчейном (`necto toolchain`)
Для создания независимых исполняемых файлов `.exe` компилятор Necto использует многоуровневое обнаружение бэкенда Clang/LLVM:
1. **Локальный каталог тулчейна Necto:** `bin/clang/bin/clang.exe` или `toolchain/clang/bin/clang.exe`.
2. **Пользовательский изолированный тулчейн:** `~/.necto/toolchain/clang/bin/clang.exe`.
3. **Системный компилятор из переменной среды PATH:** системные `clang` или `gcc`.

Команды управления тулчейном:
* `necto toolchain status` — отображение активного компилятора и его источника (`bundled`, `isolated-toolchain`, `system-clang`).
* `necto toolchain install` — настройка изолированного портативного каталога тулчейна.

## 7. Эталонная грамматика (EBNF)

```ebnf
Program         = { Statement } ;

Statement       = LetStmt
                | FnDecl
                | StructDecl
                | ImplBlock
                | EnumDecl
                | ImportStmt
                | TestBlock
                | BenchmarkBlock
                | AssertStmt
                | ReturnStmt
                | WhileStmt
                | ForInStmt
                | BreakStmt
                | ContinueStmt
                | ExprStmt ;

LetStmt         = "let" [ "mut" ] IDENT [ ":" TypeSignature ] [ "=" Expression ] [ ";" ] ;
FnDecl          = "fn" IDENT [ "[" TypeParams "]" ] "(" [ Parameters ] ")" [ "->" TypeSignature ] Block ;
ImplBlock       = "impl" IDENT "{" { FnDecl } "}" ;
StructDecl      = "struct" IDENT [ "[" TypeParams "]" ] "{" { StructField } "}" ;
EnumDecl        = "enum" IDENT "{" { EnumVariant } "}" ;
ImportStmt      = "import" "{" { IDENT } "}" "from" STRING [ ";" ] ;
TestBlock       = "test" STRING Block ;
BenchmarkBlock  = "bench" STRING Block ;
AssertStmt      = "assert" "(" Expression [ "," Expression ] ")" [ ";" ] ;

TryExpr         = Expression "?" ;
MatchExpr       = "match" Expression "{" { MatchCase } "}" ;
MatchCase       = Expression "=>" ( Block | Expression ) [ "," ] ;
```

## 8. Стабильность стандарта и гарантии обратной совместимости Necto 1.0

Начиная с версии **Necto 1.0.0**, язык вступает в фазу долгосрочной стабильности:
1. **Синтаксическая совместимость:** Все программы, написанные в соответствии с грамматикой Necto 1.0, гарантированно компилируются и выполняются без изменений во всех последующих версиях ветки 1.x.
2. **Семантическая стабильность:** Семантика сопоставления с образцом (`match`), алгебраических типов (`enum`), обработки ошибок (`Result[T, E]`, `?`), методов `impl` и стандартных модулей (`fs`, `os`, `http`, `net`) зафиксирована и не подлежит разрушающим изменениям.
3. **Стабильность CLI:** Команды тулчейна (`necto run`, `build`, `test`, `bench`, `doc`, `fmt`, `check`, `repl`, `bootstrap`) сохраняют обратную совместимость сигнатур вызова и флагов.
